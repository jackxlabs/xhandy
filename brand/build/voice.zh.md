# Xhandy 品牌语气与规则

> 由 brand.yaml v11（2026-10-20）生成。改 brand.yaml 后运行 compile.py。

## 品牌定位
- **一句话**：刷 X 时的顺手提示
- **简介**：Xhandy 是刷 X 时的顺手提示：帖子热度、你们的关系和互动记录标在每条帖子旁边，一眼看出该回哪条。
- **完整介绍**：Xhandy 是给手动玩 X 的创作者用的浏览器插件。刷 X 时，它把帖子发了多久、每小时多少浏览、你和作者是否互关、互动过几次，直接标在每条帖子旁边，一眼看出该回哪条；打字时还会提醒你别发重复回复。它从不替你点击或发送，数据只存在你的浏览器里，开源免费。
- **品类**：X 浏览器插件：给手动玩 X 的人用的提示工具；纯手动刷 + 靠脑子记；想知道关系只能点进主页或悬浮在头像上看；或者用其他 X 浏览器插件
- **定位**：给靠手动互动起号的创作者，中文和英文用户都是：Xhandy 把帖子热度、你们的关系和互动记录一起标在每条帖子旁边，一眼看出该回哪条。别的插件各管一项，Xhandy 一个全有，而且从不替你操作。

### 受众：简中蓝 V 创作者：靠手动互动起号、在意浏览和收益的中文 X 用户（核心受众，与英文用户并列）
- 痛点：不知道哪条帖子值得回；和谁互关、互动过几次只能点进主页或悬浮在头像上看，不直观

### 受众：靠手动互动起号的英文 X 用户（核心受众，与中文用户并列）
- 痛点：同上：不知道该回哪条，关系和互动记录要一个个点开才能看到

**不适合谁**
- 想全自动涨粉的人：要自动关注、自动回复、挂机互动的

**绝不做**
- 替用户操作的工具：不点击、不输入、不发送、不点赞、不关注、不取关，也不做批量动作
- 收集数据的工具：不做统计、不加载远程代码；默认不联网，联网功能（如多端同步）要用户自己打开
- 让账号看起来像机器人的加速器：关注、取关有软上限提醒，重复回复会提醒

**命名**
- 对外名称 Xhandy（X 大写，其余小写），不写 XHandy、X-handy、X Handy
- 中文文案里也写 Xhandy，不起中文名
- 仓库和本地文件夹叫 x-helper，只在开发场景出现，对外不用

**个性**
- 直白：是 标签一眼看懂，例如「2小时 · 1.5万/时」；不是 花哨的数据大屏
- 懂行：是 懂 X 的玩法：超过 48 小时变灰、重复回复会被当成垃圾；不是 爱说教
- 顺手：是 不打扰、快捷键直达、浮层不挡点击；不是 功能堆砌

**产品**
- Xhandy（已上线，v0.4.7，从 GitHub 发布页下载）：Chromium 浏览器扩展（Chrome、Edge、Brave），在 X 上显示帖子时效和每小时浏览量、关注关系、互动记忆、重复回复提醒、每日统计；关注助手和「没回关我」面板
- v0.5（计划中）：路线图：互动队列、灵感清单、引用草稿预填、导出和推送到自定义地址
- v0.6（计划中）：路线图：可选的 Notion 同步、上架商店
- later（计划中）：方向：可选的多端同步（联网，要你在设置里打开）

## 事实依据（只引用这些）
- 从不替你操作 — 不点击、不输入、不发送、不点赞、不关注；关注助手只把焦点放到 X 自己的关注按钮上，按 Enter 的是用户。端到端测试里的「插件从不自行点击」和「从不伪造鼠标或指针事件」两项保证这一点 `readme`
- 默认不联网，数据只在你的浏览器里 — 只申请「存储」和「无限存储」两个权限；没有网络请求、统计或远程代码；可导出、导入、清空。以后的联网功能（如多端同步）要你在设置里打开，联网权限到那时才申请 `readme`

- 一个插件全有 — 热度和时效标记、关注关系、互动次数和最近一次时间、重复回复提醒、每日统计、关注助手、没回关我面板，都在同一个插件里 `readme`
- 开源，免费 — 公开仓库 jackxlabs/xhandy，从 GitHub 发布页下载 `readme`
- 中英文界面 — 浏览器语言是中文时显示中文，否则英文 `readme`

## 语气
Xhandy 说话像坐你旁边的朋友：话少，但每句都有用

| 维度 | 1-5 | 说明 |
|---|---|---|
| 正式 / 随意 | 3 | 说明文的清楚，不端着也不玩梗 |
| 严肃 / 活泼 | 2 | 认真为主，偶尔一句轻松话 |
| 平实 / 专业 | 2 | 大白话，技术词换成用户看得懂的说法 |
| 克制 / 大胆 | 2 | 克制，不夸大效果，局限直接说 |

**直白**
- 要：先给结论和具体数字
- 不要：形容词堆砌、模糊的「提升」「优化」
- 改前：Xhandy 智能分析帖子热度，助你精准把握流量密码！
- 改后：每小时 1 万浏览以上的帖子标红，一眼看出哪条正火。

**懂行**
- 要：用半句话讲清 X 上为什么要这样
- 不要：说教，或者列一长串注意事项
- 改前：为了您的账号安全，请务必注意不要频繁关注他人。
- 改后：每天关注超过 20 个会提醒你：关注太快容易被限流。

**顺手**
- 要：直接说按哪个键、在哪里找
- 不要：大段功能介绍
- 改前：您可以通过使用我们精心设计的快捷键功能来大幅提升效率。
- 改后：选中帖子按 Shift+F，焦点会跳到作者的关注按钮上。

### 用词
| 用 | 不用 | 原因 |
|---|---|---|
| 帖子 | 推文、推特 | README 和界面统一用帖子；平台已改名 X |
| X | 推特、Twitter | 平台现名 |
| 互关、回关 | 互粉、回粉 | README 和界面用词 |
| 关注、取关 | 加关注、取消关注（界面里可以用全称） | README 用词，简短 |
| 提醒 | 拦截、禁止、限制 | 软上限只提醒不拦截，用错词会让人以为插件会阻止操作 |
| 浏览量 | 曝光量、流量 | 标签显示的就是 X 的浏览数 |

### 禁用词
- 保证不封号、绝对安全：太绝对，做不到保证；只能说不替你操作、有软上限提醒
- 智能、AI 分析：Xhandy 没有 AI 功能，所有标记都是规则和 X 自己的数据
- 流量密码、黑科技、神器、赋能：空洞的营销腔，和直白的个性冲突
- 永不联网、完全离线：要做多端同步等联网功能，只能说「默认不联网」
- 您：README 和界面都用「你」

术语：技术词（`Manifest V3`、`service worker`、`data-testid`）只出现在开发文档；面向用户时换成「浏览器插件」「X 改了页面」这类说法

### 写作规则
- 数字：用阿拉伯数字和真实阈值（1000/时、20 个、48 小时），不写「大量」「很多」
- 空格与大小写：产品文档（README、发版说明、商店页）中英文、数字之间空一格；Jack 个人 X 帖子按他的 x-voice-guide 紧挨着写
- 标点：不用感叹号；界面名、按钮名用「」
- 表情符号：产品文案不用表情符号；界面标签里只有 🔥（热帖）和 ⇄ → ←（关系）
- `emphasis`：加粗只用于警告和关键操作，例如「把它放在一个以后不会动的位置」
- 人称：称用户为「你」；Xhandy 用名字自称，不用「我们」
- 长度限制：能力有边界就直接说，例如「这份列表不完整」「X 可能改了数据，别信这份列表」
- 拼写：中文用简体；产品名、快捷键、X 的界面词保留英文

### 像 AI 写的句式（要改写）
- 「不是 A，而是 B」「不只是 A，更是 B」这类对比否定 例 「Xhandy 不是工具，而是你的互动伙伴」 → 直接说它做什么
- 三段排比、对仗工整的句子 例 「更快、更准、更安全」 → 挑一个，配一个数字
- 结尾升华或金句 例 「让每一次互动都有意义」 → 停在最后一个事实上
- 书面连接词 例 「说白了、本质上、值得注意的是、总的来说」 → 删掉

### 渠道
- **README**：格式：说明体：先一句话说是什么，再按功能列，配截图；中英文各一份；语气：清楚、具体
- **发布说明**：格式：用 docs/release-template.md；本版更新一两句话，写用户能感知的变化；语气：平实
- **商店页**：格式：中英文各一份（扩展的语言文件）；第一行用短版一句话介绍，正文列功能，结尾附与 X Corp 无关的声明；长度：标题 ≤ 45 字符；简短描述 ≤ 132 字符
- **产品界面**：格式：一行以内，数字在前；出错时说可能的原因和下一步，不怪用户；语气：提醒，不命令
- **X 帖子**：格式：Jack 个人号提到 Xhandy 时，用他自己的经历讲，按 jack-personal-brand 的 x-voice-guide 写；语气：Jack 的口吻

## 合规（硬性规则不满足就不能发布）
- [硬性] 说明与 X Corp 无关：不暗示是 X 官方产品或获其认可 必须包含：「Xhandy 是独立项目，与 X Corp. 没有任何关联，也未获其认可或赞助。」。 禁用：「X 官方」、「X 认证」。 适用：商店页、README、发布说明、网站。 原因：商标和商店审核；标志也刻意避开 X 官方标志的造型 `readme` 2026-10-17
- [硬性] 不把 Xhandy 说成自动化或批量工具：不写自动关注、自动回复、一键批量、涨粉神器 禁用：「自动关注」、「自动回复」、「一键批量」、「涨粉神器」。 适用：全部。 原因：产品规矩第 1 条：永远不替用户操作；这类说法也会招来 X 风控和商店审核问题 `dev-rules` 2026-10-19
- [硬性] 联网功能（多端同步、推送等）一律默认关闭，由用户在设置里打开；文案写「默认不联网」，不写「永不联网」。同步上线后，「数据只在你的浏览器里」改成「数据默认只在你的浏览器里」 禁用：「永不联网」、「完全离线」。 适用：全部。 原因：产品规矩第 2 条：联网功能由用户自己打开；多端同步要联网 `jack-2026-10-20` 2026-10-20
